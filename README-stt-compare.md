# stt-compare — 音声認識エンジンの比較

同じ発話を複数のエンジンへ**同時に**流し、結果とレイテンシを横に並べる。
社内で何を採用するかの判断材料にするための道具。

## 比べるもの

| エンジン | 必要な環境変数 | レート |
|---|---|---|
| macOS SpeechAnalyzer | （不要。常に入る） | 16kHz |
| gpt-live-transcribe (OpenAI) | `STT_COMPARE_OPENAI_KEY` | 24kHz |
| gpt-live-transcribe (Azure) | `STT_COMPARE_AZURE_URL` + `STT_COMPARE_AZURE_KEY` | 24kHz |
| gemini-3.5-transcribe-live | `STT_COMPARE_GEMINI_KEY` | 16kHz |

**鍵を渡さなければそのエンジンは比較に出ない。** 勝手に送らない。
macOS のエンジンだけは常に入る（比較の基準線になるため）。

## 使い方

```
swift run stt-compare
```

環境変数は `direnv` 等で渡す。鍵はコマンドライン引数にしない
（プロセス一覧とシェル履歴に残る）。

スペースキーで録音の開始・停止。「結果をコピー」でそのまま貼れる形になる。

## 公平に比べるために

1. **マイクは 1 回だけ開き、同じ PCM を配る。**
   エンジンごとに録り直すと、話し方の違いが結果の違いに化ける
2. **24kHz で取り込み、各エンジンの要求へ落とす。**
   16kHz から 24kHz への水増しは、された側が不利になる
3. **レイテンシは共通の基準時刻から測る。**
   初出（録音開始 → 最初の文字）と確定（停止 → 確定が出そろう）の 2 つ
4. **1 つ落ちても止めない。** 失敗したエンジンだけ失敗と出し、残りを続ける
5. **用語ヒントは全エンジンに与えないか、全エンジンに与えるか。**
   いまは与えていない（`termHints` は空）

台本欄に読み上げる文を入れておくと、コピーした結果に含まれる。
**その場で思いついた文を話すと毎回条件が変わる**ので、比較の再現性のために使う。

## gpt-live-1 について

会話モデルであって文字起こし専用ではないため、**同条件の比較にならない**。

- 確定イベントが無い（公式に "doesn't emit an authoritative turn-completed event"）
- 喋り返す。`instructions` で抑えるが、抑止する設定は文書化されていない
- 課金は無音込みの実時間で、文字起こし専用モデルの約 3 倍

プロトコルの実装（`GPTLiveWireEvent`）は入っているが、
上記の理由から既定の比較対象には入れていない。

## 注意

この道具は**3 ベンダーへ同時に音声を送る**。
実際の業務会話で試すと、顧客情報が 3 箇所へ行く。
読み上げ用の台本を用意するほうが安全で、比較としても再現性が出る。

voinp 本体と違い、設定ファイルも同意ダイアログも持たない評価用の道具である。
本体の旗印（既定では音声を外へ出さない）には影響しない
（`voinp` / `voinp-offline` のバイナリにこのコードは入らない）。
